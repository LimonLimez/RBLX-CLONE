/bugs_found
src/main.cpp was empty while CMake built a Studio target from it.
CMake tracked moving dependency branches for glm, imgui docking, ImGuizmo, stb, and glad.
CMake linked Windows libraries unconditionally and the README claimed Linux/macOS support that the Client/Server code does not currently provide.
The web backend hard-coded JWT_SECRET, allowed broad CORS, accepted avatar tokens in URLs, returned some raw database errors, and had limited input validation.
npm audit initially reported 8 vulnerabilities, including 6 high vulnerabilities through sqlite3 5.x transitive dependencies.
The game server verified tokens as only true/false and then trusted the username sent in the client CONNECT packet.
Client and server used raw packet structs without a central size/type validator.
Client receive handling dropped incomplete TCP packets instead of buffering them between recv calls.
Client and server assumed send could write full messages in one call.
Server removed players from the players map while iterating it during authentication failure.
Disconnect player-list broadcasts could still include the leaving player.
World loading accepted malformed or extreme values with little validation.
Frontend avatar/dashboard pages passed auth tokens through query strings or request bodies.
There was no web test script and no C++ protocol test target.
.gitignore ignored package-lock.json and did not cover several local config/output patterns.

/security_fixes
JWT_SECRET now comes from the environment and production refuses missing, short, or placeholder secrets.
CORS is configured from CORS_ORIGIN and is not wide open by default.
helmet is enabled.
JSON bodies are limited and API POST/PATCH/PUT requests require application/json.
Signup/login endpoints have rate limiting.
Username and password input is validated before database writes.
Avatar payloads must include all expected RGB arrays with finite values from 0 to 1.
SQL queries remain parameterized.
Raw database errors are no longer returned to clients.
Avatar endpoints require Authorization bearer tokens and no longer accept query/body tokens.
The dashboard and avatar pages no longer send tokens in URLs.
The game server uses the authoritative username from /api/verify for authenticated clients.
ServerAuth no longer sends avatar tokens in URLs and checks HTTP status codes.

/networking_fixes
Added a shared PacketProtocol namespace with packet type validation, maximum payload size, count limits, and payload size checks.
Added complete-frame parsing for TCP streams so partial packets are buffered and multiple packets in one recv are handled.
Added Network::sendAll so send paths loop until all bytes are written or a socket error occurs.
Changed Client CONNECT and PLAYER_STATE sends to use sendAll-backed packet helpers.
Changed Server welcome, world state, player list, player join, player leave, player state, and world update sends to use shared packet construction/full-send helpers.
Server now disconnects malformed packet senders cleanly instead of interpreting unchecked headers.
Server validates finite player positions, clamps health, and ignores invalid player states.
Server avoids erasing clients from the players map while iterating.

/studio_editor_fixes
Added a real Studio application entry point in src/main.cpp.
Studio loads ServerWorld.world or seeds a default world if loading fails.
Studio supports selecting parts, editing properties, adding parts, saving a world file, and using ImGuizmo move/rotate/scale.
Scale gizmo operations decompose the full returned matrix and assign clamped absolute scale. This prevents the excessive compounding behavior from GitHub issue #1.
Selected part transform edits update/rebuild physics bodies where practical.

/remaining_issues
C++ configure/build/test could not be verified here because CMake and a C++ compiler are not installed or on PATH.
The network protocol is safer but still uses raw C++ struct layouts and little-endian assumptions; a future version should use explicit field serialization.
Client.cpp remains large and should be split into networking, UI, rendering, and gameplay modules.
ServerAuth JSON parsing is intentionally small and expects the backend response shape; a real JSON parser would be safer if dependencies are allowed.
WinHTTP/WinSock still make Client and Server Windows-only.
The web backend is safer for local use but still needs HTTPS, secure cookie/session strategy, CSRF review, logging policy, backups/migrations, and deployment hardening before internet exposure.
Studio runtime behavior still needs manual testing on a machine with the C++ toolchain and graphics stack available.
